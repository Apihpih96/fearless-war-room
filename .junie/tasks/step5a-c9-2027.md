# Step 5a: Cloud9 2027 "reported roster" self-scout mode

Read `.junie/guidelines.md` first and follow its hard rules (LICENSE: only aggregates in `web/public/data/`; Python stdlib only; no `npm install`; no git commit).

## Context
A 2027 Cloud9 lineup was reported on 2026-11-23 (NOT officially confirmed): Frog (top), Blaber (jungle), Loki (mid), Yeon (bot/ADC), CoreJJ (support). Build a self-scout for this roster from each player's own games in the GRID data, on whatever team they played for, and keep the existing 2026 "Cloud9 Kia" team history (team id 47351) as an alternative.

## Data source (read-only, never copy into the repo)
- `$STL_DATA_DIR/meta/rosters.csv` (default STL_DATA_DIR = `../stl-hackathon-2026-grid-starter`, same as build_scout.py). Columns: title, series_id, game_id, game_number, team_id, team_name, side, player_id, player_name, character_id, character_name, participation_status, session. Use rows with title == "lol". Player names can have stray whitespace (e.g. "Loki "), so strip and compare case-insensitively.
- `$STL_DATA_DIR/meta/players.csv` (player_id, name, other_names, latest_team_name, team_ids, series_count, first_seen, last_seen).
- `cache/games.csv` (from extract_drafts.py) for winner_id, burned_before (Fearless-burned champions before each game), game_number, date, event. Only count roster rows whose game_id is in cache/games.csv (valid, finished games); dedupe by (game_id, player_id).
- Known IDs (verify in code, match by id first, then by name): Blaber 24165, Loki 21565, Yeon 21655, CoreJJ 24153. Frog: NO LoL player found in the data (only an unrelated Valorant team named "Frog Womp"), so Frog must come out flagged as `no_data`. Never invent a pool for him.

## 1. Python: `pipeline/build_roster.py` (stdlib, testable functions, env vars like build_scout.py)
Roster config is a constant at the top: list of {role, name, player_id or None}, label "Cloud9 2027 (reported roster)", reported date "2026-11-23", note "Reported, not officially confirmed".
Writes `web/public/data/teams/c9-2027.json` (aggregates only) with the SAME schema the app already reads from a team report (look at `teams/47351.json` and how `web/src/scout.js`, `advisor.js` and `ScoutPanel.jsx` read it) so likely picks, favorites, contested and the advisor work unchanged:
- `team`: {id: "c9-2027", name: "Cloud9 2027", season: "2027 (reported)", events: [...events players' games came from], reported: true, note}.
- `sample`: games = the sum over players of their game counts divided by number of players WITH data (rounded) is NOT ok; instead use: games = max player games, and add `sample.per_player`. Keep the keys the UI reads (series, games, wins, win_rate, by_bucket G1/G2/G3+ with games/wins/win_rate, by_side, first_pick_rate, blue_side_rate) computed over the union of the players' games from the player's team perspective; where a stat can't be defined for a mixed roster, fill a sensible value and say so in a `caveats` list.
- `champions`: one entry per champion played by any roster player, picks n/of = that player's games on it / that player's games, with record (wins-losses) and per-bucket (G1/G2/G3+) pick rates. Bans/banned_against/first_bans: zero counts with of = games (bans aren't attributable to players); add a caveat. Add `player` and `role` fields to each entry.
- `top.picks` per bucket from the above; `top.bans` empty lists.
- `fearless.favorites`: each player's most-played champion. `fearless.when_favorites_locked`: for each favorite, the player's games in G2+ where that champion was already burned (burned_before) or picked by the opponent -> replacements (champion, n/of/rate/label), locked_games, win_rate_when_locked, g1_picks, g1_win_rate, player. `fearless.by_bucket` with games/unique_champions/new_vs_g1_pool/favorite_picks as in build_scout.
- `players`: one per roster slot in role order: {player, role, player_id, status: "ok" | "thin" (<20 games) | "no_data", games, series, teams (names they played for), first_game, last_game (ISO dates YYYY-MM-DD), unique_champions, top: [{champion, games, record, win_rate}] top 8, g3plus_top}. Frog: status "no_data", games 0, empty lists.
- `roster`: {label, reported_date, note, flags: ["Frog: no games in the GRID data; top-lane pool unknown"]}.
- `insights`: 2-3 short insight objects in the same shape as build_scout's, built from the player pools (e.g. deepest pool, most-played champion overall).
Also add/merge an entry into `web/public/data/index.json` teams list: {id: "c9-2027", name: "Cloud9 2027 (reported)", season: "2027", league: "LCS", lcs_2026: false, reported: true, file: "teams/c9-2027.json", games, headline}. Make it idempotent (re-running replaces the entry; build_scout.py re-runs must not drop it: either have build_scout call it or document running build_roster.py after build_scout.py in README; prefer having build_roster.py merge so order build_scout -> build_roster works).
